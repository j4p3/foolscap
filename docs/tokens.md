# Foolscap — Token Taxonomy

Format: **W3C Design Tokens Community Group (DTCG)** JSON — `tokens/foolscap.tokens.json`.
Naming model: Nathan Curtis, *Naming Tokens in Design Systems* (Eightshapes, 2020).

## Levels

Curtis decomposes a token name into ordered levels:

```
namespace / category / concept / property / variant / state / scale
```

Foolscap applies them as:

| Level | Foolscap usage | Examples |
|---|---|---|
| **Namespace** | `fc` — applied at emission time (CSS `--fc-*`), not stored in JSON paths | `--fc-color-spruce-600` |
| **Category** | Top-level DTCG groups | `color`, `font`, `space`, `size`, `radius`, `border`, `shadow`, `motion`, `typography`, `component` |
| **Concept** | Purpose group inside a category | `surface`, `text`, `action`, `border`, `emphasis`, `feedback`, `chart` |
| **Property/variant** | The specific slot | `primary`, `raised`, `highlight`, `on-primary` |
| **State** | Interaction state suffix | `-hover` (`action.primary-hover`) |
| **Scale** | Numeric or T-shirt steps | `spruce.600`, `space.6`, `size.h2` |

## Three tiers

Following the Salesforce/Curtis model, tokens are stratified so that **each tier only
references the tier below it**:

```
COMPONENT   component.button.primary.background
                       │  "this part of this component"
                       ▼ references
SEMANTIC    color.action.primary
                       │  "ink for primary actions"
                       ▼ references
PRIMITIVE   color.spruce.700
                       │  "a value with a name"
                       ▼ resolves to
VALUE       #26453F
```

- **Primitive (reference) tokens** — `color.cream|spruce|gray|prussian|ochre|rust|olive.*`,
  `font.family|weight|size|line-height|tracking.*`, `space.*`, `radius.*`,
  `border.width|style.*`, `motion.*`. They name *values*, never purposes. UI code must
  not consume them (charts' categorical ramp is exposed through `color.chart.*`
  precisely to preserve this rule).
- **Semantic (system) tokens** — `color.surface|text|action|border|emphasis|feedback|chart.*`,
  `size.measure-*`, `size.control-height`, `shadow.plate*`, `typography.*`. They name
  *purposes* and are the primary vocabulary for application code and the Tailwind theme.
- **Component tokens** — `component.button|chip|pane|input|table|mark|graph.*`. Defined only
  where a component needs a decision that the semantic tier doesn't already state
  (e.g. `chip.selected-background`). Every value is an alias of a semantic token.
  `component.graph.*` (see `docs/graph.md`) also carries geometry — node radii, ring
  widths, dashes, hit radius — aliased to `space.*`, `border.width.*`, `border.dash.*`.

## Aliasing

DTCG curly-brace references: `"$value": "{color.action.primary}"`. The build
(`scripts/build-tokens.mjs`) resolves aliases transitively, rejects cycles and dangling
references, and emits flat CSS custom properties. Example chain, as required:

```
component.button.primary.background
  → {color.action.primary}
    → {color.spruce.700}
      → #26453F
```

## Modes

Dark ("blueprint") mode is stored per-token under
`$extensions["fc.modes"].dark` — a DTCG-conformant extension point — and emitted as
overrides under `[data-theme="dark"]`. Only *semantic* tokens carry mode overrides;
primitives are mode-invariant by definition, and component tokens inherit modes
through their semantic references.

## Composite tokens

`typography.*` uses the DTCG composite `typography` type (fontFamily, fontSize,
fontWeight, lineHeight, letterSpacing) for the four recurring voices: `masthead`,
`headline`, `prose`, `label`. The build explodes composites into per-property custom
properties (`--fc-typography-label-font-size`, …).

`border.dash.*` uses the DTCG `strokeStyle` object form
(`{ "dashArray": [...], "lineCap": "butt" }`) and is emitted as an SVG
`stroke-dasharray` list (`0.1875rem 0.125rem`), or `none` for an empty array.
String `strokeStyle` values (`border.style.*`) still emit as CSS keywords.

## Emission targets

| Artifact | Generated by | Contents |
|---|---|---|
| `dist/foolscap.vars.css` | `scripts/build-tokens.mjs` | `:root` light values + `[data-theme="dark"]` overrides, `--fc-*` |
| `dist/foolscap.theme.css` | same | Tailwind v4 `@theme` mapping utilities onto `--fc-*` vars |

Because the Tailwind theme maps onto the *custom properties* (not raw values),
runtime mode switching works with a single `data-theme` attribute and no rebuild.

## Naming rules

1. Lowercase, hyphen-separated within a level; levels joined by `-` in CSS, `.` in JSON.
2. Order fixed: category → concept → property/variant → state → scale.
3. `on-*` names ink placed *on* a colored ground (`action.on-primary`).
4. States are suffixes (`-hover`), not prefixes.
5. Numeric color scales step by lightness (50 lightest → 950 darkest), Tailwind-compatible.
6. No abbreviation of concepts (`background` stays `background`; the namespace `fc` is
   the only abbreviation in the system).
